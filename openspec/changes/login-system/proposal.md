# 变更提案：安全登录认证子系统（login-system）

## 1. 变更意图
为系统增加一套安全、可测试的账号密码登录与登出能力，作为后续用户体系、权限体系的基础模块。

## 2. 范围

### 2.1 本期包含
- 登录入口与前端交互约定
- 账号 / 密码输入校验
- 核心认证流程（加盐哈希校验）
- 登录态维持（Cookie / Session，含「记住我」区分长短有效期）
- 退出登录
- 异常与边界场景处理
- 安全加固：失败次数限制、验证码、IP 限流、账号枚举防护
- 可测试的验收标准

### 2.2 本期不包含
- 用户注册
- 找回 / 重置密码
- SSO、MFA、第三方登录、扫码登录（列为后续规划）
- 账号权限 / 角色管理

## 3. 影响范围
- Auth Service / 用户认证接口层
- Session Store（Redis / DB）与 Cookie 策略
- 登录页 / 前端表单
- 审计日志与监控
- 网关 / WAF 的 IP 限流配置

## 4. 风险与缓解

| 风险 | 缓解措施 |
| --- | --- |
| 暴力破解 | 连续失败锁定 + 验证码 + IP 限流 |
| 账号枚举 | 账号不存在与密码错误统一返回「账号或密码错误」 |
| 会话劫持 | HttpOnly / Secure / SameSite Cookie；短有效期；服务端可控注销 |
| 锁导致可用性下降 | 渐进式锁定策略；支持人工/后台解锁 |
| 密码泄露 | bcrypt / Argon2 加盐哈希；禁止明文存储 |

## 5. 上线与回滚策略
- 首次随版本全量上线，无数据迁移。
- 回滚：关闭登录接口或返回维护状态；避免在回滚期间产生 Session 数据不一致。
