## 3. 数据模型

```
TodoItem {
  name:        string   // 必填；trim 后非空；长度 ≤ 50
  description: string   // 选填；不限长度；原样保存（可为空字符串）
}
```

- 存储介质：浏览器 `localStorage`
- 存储键：`todos`
- 存储值：`TodoItem[]` 的 JSON 序列化字符串，**按创建先后追加**
- 不引入 `id`、`createdAt`、所属日期、创建人、优先级、完成状态等字段（本期未纳入范围，遵循 YAGNI）
- 因无 `createdAt` 字段，"最新在最上"的展示顺序由渲染时对数组做倒序遍历实现，存储顺序保持追加序不变

**Tab 标识唯一性校验**：现有 `switchTab()`（`index.html:117`）使用选择器 `.tab-btn[onclick*="<tab>"]`。现有三个标识为 `helloworld`、`hash`、`bubblesort`，均不包含子串 `todo`，故 `todo` 作为新标识不会误匹配。

### 4.2 逻辑单元

| 函数 | 职责 | 依赖 |
|---|---|---|
| `validateTodo(name, description)` | 校验入参，返回错误文案字符串；校验通过返回 `null` | 无 |
| `loadTodos()` | 从 `localStorage` 读取并解析为数组；任何异常降级为 `[]` | `localStorage` |
| `saveTodos(list)` | 序列化并写入 `localStorage`；返回布尔值表示是否成功 | `localStorage` |
| `renderTodoList()` | 读取当前列表并倒序渲染到 `#todoList`；空态渲染占位文案 | `loadTodos()` |
| `createTodo()` | 编排入口：取值 → 校验 → 读 → 追加 → 写 → 重渲染 → 清空表单 → 提示 | 上述四者 |

每个单元职责单一、通过明确入参/返回值通信，可独立阅读与替换。

## 5. 数据流

```
用户输入名称/描述
      ↓
createTodo() 取值（原始字符串）
      ↓
validateTodo() ──校验失败──→ 提示区显示错误文案，流程终止（不写入、不清空表单）
      ↓ 校验通过
loadTodos() 读取现有数组
      ↓
追加 { name: <trim 后>, description: <原样> }
      ↓
saveTodos() 写回 ──写入失败──→ 提示"本地存储不可用，本次创建未保存"，流程终止（该条不进入列表）
      ↓ 写入成功
renderTodoList() 重渲染只读列表
      ↓
清空 #todoName / #todoDesc，提示区显示"创建成功"
```

## 6. 校验与错误处理

### 6.1 输入校验

| 场景 | 判定 | 行为 | 提示文案 |
|---|---|---|---|
| 名称为空或全为空白字符 | `name.trim() === ''` | 拒绝创建，不写入，保留用户已输入内容 | `请输入事项名称` |
| 名称超过 50 字 | `name.trim().length > 50` | 拒绝创建，不写入 | `事项名称不能超过 50 字` |
| 描述为空 | — | 正常创建，`description` 存为空字符串 | — |
| 描述超长 | — | 不做长度限制，原样保存（D6） | — |

**长度计数口径**：「50 字」以 JavaScript `String.length`（UTF-16 码元）计数，与 `<input maxlength="50">` 的浏览器计数口径一致。BMP 内的中英文字符各计 1； emoji 等代理对字符计 2。两者口径统一，不会出现输入框允许但校验拒绝的不一致。

说明：`<input maxlength="50">` 已在输入层限制原始字符数为 50，`validateTodo()` 的长度判定作为粘贴/自动填充/程序化赋值场景的第二道防线保留。存入的 `name` 为 `trim()` 后的值。

### 6.2 存储异常

| 场景 | 行为 |
|---|---|
| `localStorage` 中 `todos` 不存在 | 视为空数组 `[]` |
| `todos` 值为非法 JSON，或解析结果不是数组 | 静默降级为空数组 `[]`，同时 `console.warn` 记录；不向用户弹错。本期**不做**主动修复或备份：损坏值会保留在 `localStorage` 中，直到下一次创建成功时由 `saveTodos()` 以新数组整体覆盖（此时损坏数据丢失，属可接受行为——该场景仅在外部手工篡改存储时出现） |
| 写入抛出 `QuotaExceededError`（描述不限长度，单条过大可能触发配额） | 捕获异常，提示区显示 `本地存储不可用，本次创建未保存`；该条**不**进入渲染列表，保证界面与存储一致 |
| 写入抛出 `SecurityError`（隐私模式/存储被禁用） | 同上 |
| 读取抛出任何异常 | 降级为空数组，渲染空态 |

### 6.3 渲染安全

`renderTodoList()` 构建列表节点时**必须使用 `textContent` 赋值**，禁止使用 `innerHTML` 拼接用户输入，避免名称/描述中的 `<`、`>`、`&` 破坏布局或造成脚本注入。

### 6.4 空态

列表为空时，`#todoList` 渲染文案：`暂无待办事项`。

### 6.5 列表项展示

每项展示两行：第一行为 `name`；第二行为 `description`，当 `description` 为空字符串时不渲染第二行。列表项**不显示序号、不显示任何操作按钮**（只读回显，D2）。

### 6.6 提示区行为

每次点击「创建」时先清空 `#todoMsg`，再写入本次结果文案，避免上一次的错误或成功提示残留造成误读。页面首次加载时 `#todoMsg` 为空。

- 处理决定：**本期不修复**。该问题源于后端缺失，与待办功能无因果关系；按 brainstorming「不做无关重构」原则排除在范围外，仅在此记录以免实现者误判。
