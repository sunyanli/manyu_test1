# 待办事项功能设计文档

**日期**: 2026-09-09  
**状态**: 设计阶段  
**范围**: MVP — 仅创建

---

## 1. 概述

在现有 `index.html` 单页应用中新增「待办事项」Tab，帮助用户记录日常待办事项。MVP 仅支持创建，数据存储在浏览器 localStorage。

## 2. 集成方式

在 `index.html` 现有 Tab 栏（HelloWorld / Hash / 冒泡排序）中新增「待办事项」Tab，与现有功能并列。

## 3. 数据模型

**存储键**: `todo_items`（localStorage）

**数据格式**: JSON 数组，每项结构：

```json
{
  "id": "1725878400000",
  "name": "完成周报",
  "description": "汇总本周工作内容",
  "createdAt": "2026-09-09T10:00:00.000Z"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✓ | 唯一标识，`Date.now()` 生成 |
| `name` | string | ✓ | 待办名称，用户输入 |
| `description` | string | | 待办描述，用户输入，可为空 |
| `createdAt` | string | ✓ | ISO 8601 创建时间戳 |

## 4. UI 设计

### 4.1 布局

上方创建表单 + 下方待办列表，上下排列。

```
┌─────────────────────────────────────┐
│  [名称 *]  [描述]  [+ 添加]          │  ← 表单行
├─────────────────────────────────────┤
│  ● 完成周报                          │
│    汇总本周工作内容                    │  ← 列表项
│  ● 提交报销                          │
│    差旅费报销单                       │
└─────────────────────────────────────┘
```

### 4.2 创建表单

- **名称输入框**：`<input type="text">`，placeholder "待办名称"，必填
- **描述输入框**：`<input type="text">`，placeholder "待办描述（可选）"，可选
- **添加按钮**：`<button>`，点击触发创建

### 4.3 待办列表

- 只读展示，最新创建的项显示在列表顶部
- 每项显示名称（加粗）和描述（灰色小字）
- 列表为空时显示占位提示："暂无待办事项"

### 4.4 样式

复用现有 `index.html` 的 CSS 体系：`.op-row`、`.btn`、`.btn-primary`、`.result-box` 等类名，保持视觉一致。

## 5. 交互流程

1. 用户在表单中输入名称和描述
2. 点击「添加」按钮
3. 前端校验：名称为空时弹出提示，阻止提交
4. 校验通过后，生成 id（`Date.now()`）和 `createdAt`（`new Date().toISOString()`）
5. 将新项追加到 localStorage `todo_items` 数组头部
6. 列表即时刷新，新项出现在顶部
7. 表单清空，名称输入框获得焦点

## 6. 改动范围

| 文件 | 改动类型 | 说明 |
|------|----------|------|
| `index.html` | 修改 | 新增 Tab 按钮、Tab 面板 HTML、JS 逻辑 |

**不改动任何后端代码**，纯前端方案。

## 7. 不包含

- 编辑、删除、完成/勾选待办项
- 排序、筛选、搜索
- 截止日期、优先级、标签等扩展字段
- 多设备同步、云端存储
- 后端 API

## 8. 验收标准

- 页面加载后可在 Tab 栏看到「待办事项」按钮
- 点击按钮切换到待办事项面板
- 输入名称和描述，点击添加，待办项出现在列表中
- 名称为空时点击添加，提示用户且不创建
- 刷新页面后，之前创建的待办项仍然存在
- 样式与现有页面风格一致
